## ۱. اصول معماری

1. **API-first:** همه قابلیت‌ها از `‎/api/v1` سرو می‌شوند؛ Swagger زنده از کد تولید شود (`‎/docs`).
2. **DB per service:** هر میکروسرویس اسکیمای خودش را دارد؛ ارتباط بین سرویسی فقط API یا ایونت، هرگز join مستقیم.
3. **مالی event-driven + idempotent:** پرداخت، اسکرو، بازگشت وجه، تسویه از صف می‌گذرند؛ `Idempotency-Key` در `POST /payments` الزامی؛ retry خودکار برای عملیات مالی ممنوع (فقط دکمه دستی).
4. **Snapshot مالی:** `order_items.snapshot` و `invoices.items_snapshot` و نسخه آدرس ثبتی در لحظه سفارش قفل می‌شوند.
5. **Soft delete + Audit:** هیچ رکوردی حذف فیزیکی نمی‌شود؛ همه اقدامات ادمین/مالی در `audit_logs` (کاربر، زمان، IP، قبل/بعد).
6. **پیک نقش سیستمی نیست:** بدون اکانت، بدون سطر در ماتریس دسترسی؛ فقط لینک وب تک‌سفارش با توکن یکتا و انقضای ۲۴ ساعته.

## ۲. کانتکست و مدل Store-Delivered

- **اکتورها:** مشتری، فروشنده (۱۰ نوع)، ارائه‌دهنده خدمت (زیرمجموعه فروشنده)، ادمین (Super / پشتیبانی / اکانتنت / مالی)، سیستم (jobها). پیک اکتور خارجی بدون لاگین.
- **مدل ارسال:** AMPET واسط پرداخت و ارتباط است؛ ارسال و هزینه ارسال با فروشگاه است. سبد چندفروشگاهی = N سفارش مستقل، یک پرداخت یکجا، تسویه جداگانه پس از تحویل هر سفارش با کد ۶ رقمی + عکس بسته.

### ۲.۱ ده نوع فروشنده و قانون ترکیب

پت‌شاپ، گرومر، کلینیک، بیمارستان، مطب دامپزشک، متخصص دام بزرگ، پانسیون، بیمارستان+پانسیون، عمده‌فروش، واردکننده.
فقط ۲ ترکیب مجاز: `بیمارستان+پانسیون` و `پت‌شاپ+کلینیک`. تغییر نوع = بازگشت به «در انتظار تأیید» + حذف موقت سرویس‌های ناسازگار.

### ۳.۱ کرالر و مستر کاتالوگ (فریز شده ۱۴۰۵/۰۷/۱۴)
- مدل: `master_products` (مال AMPET، فقط ادمین) + `listings` (مال فروشنده: `master_id + price + stock`). ثبت محصول دستی توسط فروشنده ممنوع.
- ۴ منبع قطعی (تأیید ۱۴۰۵/۰۷/۱۴): (۱) دیجی‌کالا — بیس‌لاین قیمت و کشف کالای جدید، کرال روزانه؛ (۲) باران پت — عمق برندهای تخصصی، روزانه؛ (۳) اصفهان پت — عمق برندهای تخصصی و راستی‌آزمایی قیمت، روزانه؛ (۴) سایت رسمی برندها (رویال‌کنین و مشابه) — حقیقت نام/بارکد/عکس، ماهانه. دارو/مکمل فقط با تأیید دستی ادمین وارد مستر می‌شود.
- قواعد: احترام به robots، سقف ۱ درخواست/۳ ثانیه، User-Agent شفاف، قیمت خارج از `میانه ±۴۰٪` بلاک می‌شود.

## ۶. طراحی API

- سبک `REST + JSON (UTF-8)`، مسیر `‎/api/v1/...`، مستند `OpenAPI 3.0` در `‎/docs`، حداکثر بدنه ۵MB.
- هدرها: `Authorization: Bearer <JWT>`، `X-Device-Id` + `X-Platform`، `X-Request-Id`، `Accept-Language: fa-IR`، `Idempotency-Key` در پرداخت.

### ۶.۱ نشست

| مورد | قاعده |
|------|-------|
| Access JWT | ۱۵ دقیقه (ادمین ۱۰ دقیقه + 2FA اجباری مالی/Super) |
| Refresh | ۳۰ روزه چرخشی (rotation) |
| ورود | `POST /auth/otp/request` → `POST /auth/otp/verify` |
| لینک پیک | توکن تک‌منظوره ۲۴ ساعته، خارج از JWT |

### ۶.۲ ساختار پاسخ

موفق: `{success:true, data:{}, meta:{page,per_page,next_cursor,total}}` — خطا: `{success:false, error:{code,message,details[],request_id}}` با `message` فارسی کاربرپسند از بخش UI Copy.

### ۶.۳ خطاها

| HTTP | کاربرد | نمونه code |
|------|--------|------------|
| 200/201 | موفق / ایجاد شد | — |
| 400 | بدنه نامعتبر | `VALIDATION_ERROR` |
| 401 | توکن | `TOKEN_EXPIRED` |
| 403 | نقش | `FORBIDDEN_ROLE` |
| 404 | نیافت | `NOT_FOUND` |
| 409 | تداخل | `HOLD_EXPIRED`, `ORDER_STATE_CONFLICT` |
| 422 | منطقی | `STOCK_UNAVAILABLE`, `CANCEL_NOT_ALLOWED`, `RETURN_WINDOW_CLOSED`, `DISCOUNT_*`, `REFERRAL_*`, `TERMS_NOT_ACCEPTED` |
| 429 | سقف نرخ | `RATE_LIMIT_EXCEEDED` (+ هدر `Retry-After`) |
| 500/502 | داخلی / درگاه | `INTERNAL_ERROR`, `PAYMENT_GATEWAY_FAILED` |

### ۶.۴ صفحه‌بندی و Rate Limit

`?page=&per_page=` (۲۰ پیش‌فرض، ۱۰۰ سقف)، فیدها cursor-based، `?sort=created_at:desc`، فیلتر شفاف (`animal, min_price...`)، تاریخ ISO.
سقف‌ها: OTP سه درخواست در ۱۰ دقیقه؛ verify سه تلاش سپس قفل ۱۵ دقیقه؛ عمومی ۶۰/دقیقه؛ پرداخت ۱۰/دقیقه؛ ادمین ۱۲۰/دقیقه.

### ۶.۵ Endpointهای مرجع (ثابت)

Auth: `/auth/otp/request, /verify, /refresh, /logout` — User: `/me, /me/delete-request, /me/sessions` — Address/Pet: `/addresses, /pets, /pets/{id}/records|vaccinations, /pets/share/{token}` — Catalog/Cart: `/products, /categories, /cart, /cart/items, /cart/validate, /cart/hold-status` — Order/Payment: `/orders, /orders/{id}/cancel-request, /payments, /payments/{id}/verify, /wallet, /wallet/transactions|withdrawals, /refunds` — RMA: `/returns, /returns/{id}/shipping-method|tracking-code` — Booking: `/bookings, /bookings/{id}/cancel|reschedule` — Provider: `/providers, /provider-applications` — Chat/Review: `/threads, /orders/{id}/reviews, /favorites, /discounts/apply, /referral, /tickets, /notifications, /articles|faq` — Admin: `/admin/**` (نقش + 2FA). سازگاری: حداقل ۲ نسخه API همزمان، sunset حداقل ۶ ماهه.

## ۷. جریان‌های حیاتی (با SLA الزام‌آور)

### ۷.۱ Auth / OTP
کد ۵ رقمی، اعتبار ۱۲۰ ثانیه، ۳ اشتباه → قفل ۶۰ ثانیه، سقف ۳ ارسال در ۱۰ دقیقه. نقش پیش‌فرض مشتری؛ فروشنده پس از تکمیل مدارک می‌رود به «در انتظار تأیید».

### ۷.۲ تأیید فروشنده
ثبت‌نام → تکمیل مدارک اختصاصی نوع → `PENDING` → صف ادمین (مرتب قدیمی‌ترین + شمارش SLA) → چک‌لیست ۵ موردی (شناسه/شبا/آدرس/نوع/تصویر) → یکی از ۴ تصمیم (تأیید/رد/نقص/بازبینی، دلیل اجباری). نقص = مهلت ۷ روز وگرنه رد خودکار. تأیید = سطح «تازه‌کار» + ۷ روز مهلت ثبت اولین محصول. بازبینی دوره‌ای ۶ ماهه.

### ۷.۳ تأیید محصول
پیش‌بررسی خودکار ۱۰ شرطی (۳ تا ۱۲ تصویر، عنوان ۱۰-۸۰، توضیح ۵۰+ حرف، قیمت مثبت در رنج دسته، موجودی ≥۱، دسته سازگار، نوع حیوان، بدون کلمه ممنوعه، تصویر ≤۵MB و JPG/PNG، بدون لوگوی بیگانه روی تصویر اصلی) → `PENDING_REVIEW` → یادآوری ادمین ۴h/هشدار ۱۲h → چک‌لیست ۱۰ موردی → انتشار یا رد (۳ تلاش، سپس تعلیق ثبت ۷ روزه). ویرایش فیلد حساس (قیمت/موجودی/تصویر اصلی/دسته/حیوان/عنوان) یا افزایش >۲۰٪ قیمت در ۳۰ روز = بازگشت به صف. SLA: ۲۴h عادی، ۷۲h دارو/بهداشتی.

### ۷.۴ موجودی (Anti-Oversell)
Hold از لحظه افزودن به سبد: عادی ۱۵ دقیقه / شلوغ حداکثر ۵ دقیقه (روشن دستی ادمین یا خودکار با N سفارش در ۵ دقیقه)، ورود به چک‌اوت تمدید تا ۲۰ دقیقه + re-validate، کلیک پرداخت تمدید تا ۳۰ دقیقه + اعتبارسنجی نهایی قبل از باز شدن درگاه، کسر قطعی با Row Lock پس از callback موفق. Job آزادسازی هر ۳۰ ثانیه. نبود موجودی پیش از درگاه: پیام دقیق + حذف/ناموجود + جایگزین + کوپن ۵٪ (۷ روزه) + «اطلاع‌رسانی موجودی». وضعیت‌ها: موجود (>۵)، کم (≤۵)، رزروشده، ناموجود، پیش‌فروش.

### ۷.۵ سفارش و لغو سخت‌گیرانه
پرداخت‌نشده ۲h → لغو خودکار؛ پرداخت‌شده پیش از تأیید فروشنده = لغو رایگان ۱۰۰٪؛ پس از تأیید فقط «درخواست لغو» (دلیل اجباری) → ۲۴h فرصت فروشنده → تأیید/رد/عدم‌پاسخ (=رد خودکار به نفع فروشنده) → تیکت به ادمین (۲۴h). فروشنده لغو کند: ۱۰۰٪ + کوپن ۵٪ + امتیاز منفی ۰٫۵. عدم تأیید ۲۴h → لغو خودکار. چندفروشگاهی مستقل.

### ۷.۶ کد تحویل ۶ رقمی + لینک وب پیک
صدور هنگام «در حال ارسال» (پوش+پیامک)، انقضا ۲۴h، ۳ تلاش اشتباه → قفل ۱۵ دقیقه + هشدار. تحویل = کد صحیح + نام گیرنده/نسبت + عکس بسته (اجباری) + ساعت/نام پیک. درخواست کد جدید: فروشنده (با دلیل) / مشتری (هر ۴h) / پیک (از داخل لینک) — سقف مشترک ۳ صدور؛ کد قبلی فوراً باطل، لینک جدید صادر. پس از سقف: دکمه غیرفعال + تیکت خودکار پس از ۲۴h بی‌تحویلی. لینک وب: توکن یکتا، بدون اپ/ثبت‌نام، پس از تحویل باطل.

### ۷.۷ اسکرو، تسویه، بازگشت وجه
پرداخت یکجا → اسکرو نزد AMPET → آزادسازی پس از تحویل موفق منهای کارمزد (قابل تنظیم ادمین) به کیف پول فروشنده (دو بخش: قابل برداشت / در انتظار تسویه + شمارش معکوس). چرخه ۱: ۳۰ روز از **نخستین فروش تحویل‌شده** (نه ثبت‌نام)؛ چرخه ۲ به بعد هر ۱۴ روز. برداشت زودهنگام چرخه ۱ ممنوع؛ چرخه ۲+ با کارمزد ۲٪ + تأیید ادمین. واریز ۳ تلاش خودکار (۱۵ دقیقه فاصله) وگرنه صف دستی + تیکت. **بازگشت وجه همیشه به کیف پول AMPET در ۰ تا ۱۰ ثانیه**؛ برداشت بانکی در چرخه ۱۴ روزه؛ بالای ۵ میلیون = تأیید دوم. خطای درگاه = ۷۲h کاری.

### ۷.۸ مرجوعی (RMA)
مهلت ۷ روز، عکس اجباری، استثنا (غذای بازشده، دارو، بهداشتی، سفارشی، حیوان زنده). فروشنده ۴۸h تصمیم (بی‌پاسخ = تأیید خودکار) → ۷۲h انتخاب روش (پیک خودش / پست با کد رهگیری / حضوری در آدرس ثبتی؛ بی‌انتخاب = پست پیش‌پرداخت با هزینه فروشنده) → مشتری ۵ روز تحویل کالا → انبار ۷۲h بررسی (بی‌پاسخ = تأیید خودکار + بازگشت). هزینه: خرابی/اشتباه/ناقص/مغایرت/پشیمانی با فروشنده؛ عدم حضور/آدرس اشتباه با مشتری (کسر از بازگشت). اعتراض ۷ روزه → ادمین ۲۴h تصمیم نهایی.

### ۷.۹ رزرو نوبت
`DRAFT → PENDING_PROVIDER (24h) → CONFIRMED (پرداخت 2h) → PAID → COMPLETED` + شاخه‌های `REJECTED/AUTO_REJECTED/AUTO_CANCELLED_UNPAID/NO_SHOW/RESCHEDULE_PENDING/DISPUTE`. جریمه مشتری: >۲۴h رایگان، ۲۴ تا ۲h مانده ۳۰٪، <۲h یا No-show صددرصد. لغو ارائه‌دهنده: ۱۰۰٪ + ۱۰٪ جریمه نقدی از کیف پولش + امتیاز منفی؛ ۵ لغو در ۳۰ روز = تعلیق ۷ روزه. تغییر زمان حداکثر ۲ بار، تا ۲۴h قبل رایگان.

### ۷.۱۰ یادآوری، جستجو، تخفیف، وفاداری (خلاصه فنی)
یادآوری: Job هر ۵ دقیقه، یکتایی `user+code+ref`، fallback پوش→پیامک (۳۰ دقیقه)، سکوت ۲۱ تا ۹ (غیرمالی)، حداکثر ۳ غیرمالی در روز. جستجو: autocomplete از ۲ حرف (≤۸ پیشنهاد)، وزن‌ها (عنوان ۳۰ / نظر ۱۵ / پرفروش ۱۵ / فروشنده ۱۰ / موجودی ۱۰ / بازدید ۵ / CTR پنج / تازگی ۵ / مسافت ۵)، ایندکس لحظه‌ای، p<۳۰۰ms، صفحه ۲۰تایی، Ads جدا (رتبه ۱-۳ با نشان تبلیغ). تخفیف: فقط ۱ کد در سفارش (قابل جمع با امتیاز/کیف پول/BNPL)، Anti-Abuse با سقف IP/دستگاه. وفاداری: ۱ امتیاز=۱۰۰ تومان، حداقل مصرف ۱۰۰۰، سقف ۲۰٪ سبد، سطوح برنزی/نقره‌ای۱۰۰۰/طلایی۵۰۰۰/پلاتینیوم۱۵۰۰۰ (لغزش ۱۲ ماهه + پایداری ۳ ماهه).
