## ۱. هدف، Deliverable و خارج از اسکوپ

- **هدف:** ساخت زیرساخت تکرارپذیر (ریپو، کانتینر، CI) و قراردادهای سراسری (پاسخ/خطا، نرخ‌گیر، Swagger، مهاجرت ERD، دیزاین‌سیستم) به‌طوری که SP-01 تا SP-16 فقط «فیچر» اضافه کنند و هیچ SPای پایه را از نو ننویسد. خروجی قابل تحویل M0 طبق ماده ۳.۱: **لینک ریپو + آدرس `dev` + سند بک‌لاگ**.
- **Deliverable (تحویل‌نامه):**
  - ریپوی Git با `main` + تاریخچه از روز اول روی حساب GitHub کارفرما با دسترسی ادمین کارفرما (ماده ۶.۲)
  - `docker-compose.yml` با سرویس‌های `postgres:16` + `redis:7` + `minio` (healthcheck + volume + پورت‌های مشخص) — دقیقاً طبق `PLAN-EXECUTION-LEAN §۳`
  - مونوریپو: `apps/api/` (NestJS مونولیت ماژولار با ماژول‌های `auth, user, marketplace, payment, admin`)، `apps/app/` (Flutter)، `apps/web-admin/` (Next.js)، `docs/`
  - لایه قرارداد سراسری در `apps/api/src/common/`: interceptor پاسخ استاندارد `{success,data,meta}`، exception filter `{success:false,error:{code,message,details,request_id}}`، میدل‌ور `X-Request-Id` (UUID) + لاگ مسیر/زمان/کد بدون PII
  - کاتالوگ کدهای خطا: `docs/error-codes.md` + `apps/api/src/common/error-codes.ts` (همه کدهای §۴ پروژه‌داک)
  - گارد RateLimit سراسری با سقف‌های ثابت: عمومی **۶۰/دقیقه**، پرداخت **۱۰/دقیقه**، ادمین **۱۲۰/دقیقه**، OTP **۳ درخواست/۱۰ دقیقه** (پاسخ 429 + هدر `Retry-After`)
  - Swagger UI زنده در `‎/docs` (OpenAPI 3.0 تولیدی از دکوراتور)
  - مهاجرت‌های ERD پایه (گروه Auth/User از ERD §۱): جداول **`users, user_roles, otp_codes, sessions, audit_logs`** + ایندکس `users.phone UNIQUE` + تریگر append-only روی `audit_logs`
  - ۶ فایل مهاجرت **placeholder** برای گروه‌های ۲ تا ۷ ERD (آدرس/حیوان، کاتالوگ/موجودی، سبد/سفارش، مالی، رزرو، تعامل/رشد) — فقط فایل و کامنت « RESERVED — اجرا در SP-XX»، بدون جدول
  - دیزاین‌سیستم: توکن‌های رنگ `#0F5D4A` / `#D4AF37` / `#111827` / `#F9FAFB`، فونت **Vazirmatn**، RTL کامل، **۱۳ کامپوننت استاندارد** (Button/Input/Chip/Card/Badge/Bottom Sheet/Modal/Toast ۳s/Skeleton/Empty/TabBar/Pull-to-Refresh/Pagination) در `apps/app/lib/design/` + همان توکن‌ها در `apps/web-admin/styles/tokens.css`
  - `.env.example` بدون هیچ سکرت واقعی (ماده ۶.۳) + راهنمای `README-dev.md` (نصب، `docker compose up`، `flutter run`، `npm run test`)
  - Adapter پیامک **mock** (لاگ کنسول + فایل `logs/sms-mock.log` با همان امضای interface کاوه‌نگار) و Adapter درگاه **mock** — طبق `PLAN §۱`
  - CI: `.github/workflows/ci.yml` = `lint` + `unit test` + `contract test` روی Postgres سرویس‌شده در CI
  - سند `docs/backlog.md` (بک‌لاگ اسپرینت‌ها/SPها) — خروجی رسمی M0
- **خارج از اسکوپ این SP:**
  - پیاده‌سازی OTP/JWT/RBAC/پروفایل → **SP-01**
  - جداول و API آدرس/حیوان/پذیرش قوانین → **SP-02**
  - جداول کاتالوگ، سبد، سفارش، مالی، رزرو (فقط placeholder خاموش) → **SP-03 تا SP-09**
  - پنل ادمین کامل (۴۸ صفحه) و ویرایش ماتریس دسترسی → **SP-15**
  - استقرار واقعی `staging/prod`، دامنه نهایی، بکاپ، مانیتورینگ → **SP-16**
  - پیامک واقعی کاوه‌نگار و درگاه واقعی → **SP-11 / SP-07**
  - RabbitMQ و Elasticsearch (حذف‌شده در `PLAN §۱` — queue داخلی + `ILIKE`/`pg_trgm`)

- **سناریوی دستی گام‌به‌گام (برای کارفرما بدون دانش برنامه‌نویسی):**
  1. ترمینال → رفتن به پوشه ریپو → اجرای `docker compose up -d` → انتظار: سه سرویس `healthy` (خطای قرمز نباشد).
  2. مرورگر → `http://localhost:3000/docs` → انتظار: صفحه Swagger باز شود و عنوان `/api/v1` دیده شود.
  3. در Swagger گزینه `GET /api/v1/health` را Execute می‌کنید → انتظار: پاسخ `{"success":true,...}`.
  4. درخواست POST بدون بدنه → انتظار: `{"success":false,"error":{"code":"VALIDATION_ERROR","message":"…","request_id":"…"}}` با **متن فارسی** (نه انگلیسی).
  5. ابزار `curl` → ارسال ۶۱ بار پشت‌سرهم یک درخواست عمومی → انتظار: بار ۶۱ = کد 429، `code=RATE_LIMIT_EXCEEDED` و هدر `Retry-After`.
  6. `npm run lint && npm test` → انتظار: همه سبز، بدون خطا.
  7. `flutter run` روی گوشی → انتظار: صفحه با فونت Vazirmatn، چیدمان راست‌چین، دکمه اصلی سبز `#0F5D4A`.
  8. در Gallery دیزاین‌سیستم، ۱۳ کامپوننت را با `text-scale=130٪` ببینید → انتظار: هیچ متن بریده/همپوشان نشود.
  9. `docker compose down -v && docker compose up -d && npm run db:migrate` → انتظار: ۵ جدول Auth/User از صفر ساخته شود.
  10. `npm run db:migrate:down` → انتظار: برگشت کامل بدون خطا (ماده ۸.۵).
  11. فایل `logs/sms-mock.log` را باز کنید → انتظار: رکورد قالب `SMS-OTP` با کد ۵ رقمی ثبت شده باشد.
  12. `.env.example` را باز کنید → انتظار: **هیچ کلید واقعی/رمزی** در فایل نباشد.
- **خطاهای پرتکرار این SP:**

  | HTTP | code | شرط بروز |
  |------|------|----------|
  | 400 | `VALIDATION_ERROR` | بدنه/پارامتر نامعتبر |
  | 401 | `TOKEN_EXPIRED` | بدون توکن یا منقضی (پیش‌نویس SP-01) |
  | 403 | `FORBIDDEN_ROLE` | نقش ناکافی |
  | 404 | `NOT_FOUND` | مسیر/رکورد ناموجود |
  | 429 | `RATE_LIMIT_EXCEEDED` | عبور از سقف ۶۰/۱۰/۱۲۰ در دقیقه + هدر `Retry-After` |
  | 500 | `INTERNAL_ERROR` | خطای داخلی + ثبت در لاگ با `request_id` |
  | 502/503 | `PAYMENT_GATEWAY_FAILED` | خرابی درگاه (فقط جای‌گاه در کاتالوگ) |
