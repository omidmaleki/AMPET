## ۱. هدف، Deliverable و خارج از اسکوپ

**هدف:** ساخت «مستر کاتالوگ» متعلق به AMPET که فقط از مسیر کرالر ۴ منبع تغذیه می‌شود و پس از تأیید دستی ادمین منتشر می‌شود؛ هر قلم بازه ۳۰ روزه قیمت (`min_30d / median_30d / max_30d`) می‌گیرد و هر قیمت خارج از `میانه ±۴۰٪` بلاک می‌شود. مالکیت مستر با AMPET است: **فقط ادمین/کرالر می‌نویسند، فروشنده هرگز محصول دستی نمی‌سازد.** خروجی نهایی: درخت `categories` + حداقل **۵۰۰ قلم مستر تأییدشده** + صف تأیید ادمین با SLA ۲۴ ساعته (دارو ۷۲ ساعته).

**Deliverable:**

- **جداول (نام ثابت ERD):** `categories` (درختی با `parent_id`)، `master_products` (`id, brand, title_norm, barcode, images, specs(JSON), category_id, animal_types, status` + فیلدهای افزوده `source, source_url, crawled_at, requires_manual_approval`)، `price_bands` (`master_id, min_30d, median_30d, max_30d, updated_at`)، `product_variants` (`master_id, sku, attrs(JSON)`)، `audit_logs` (تصمیمات ادمین). صف کرالر = ستون `status` در `master_products` (**بدون جدول جدید**).
- **Endpointها (همه زیر `/api/v1`، پاسخ `{success,data,meta}`):**

| مسیر | نقش | توضیح |
|------|-----|-------|
| `GET /categories` | عمومی | درخت دسته‌ها (API §8 — Catalog) |
| `GET /admin/master-products?status=&source=&category_id=&page=&per_page=` | ادمین | صف کرالر، مرتب قدیمی‌ترین اول |
| `GET /admin/master-products/{id}` | ادمین | جزئیات + منابع + `price_bands` + تاریخچه |
| `POST /admin/master-products/{id}/approve` | ادمین | انتشار؛ **تنها مسیر ورود دارو/مکمل به مستر** |
| `POST /admin/master-products/{id}/reject` | ادمین | رد با ذکر دلیل (اجباری) |
| `PUT /admin/master-products/{id}/price-band` | ادمین | اصلاح دستی بازه |
| `POST /admin/crawler/run` | ادمین | اجرای دستی/زمان‌بندی‌شده + ثبت در `audit_logs` |

- **صفحات Flutter:** `wireframes/store.png` — درخت دسته‌ها + حالت خالی «این دسته فعلاً خالی است»؛ بدون نمایش قیمت (قیمت از SP-05).
- **صفحات وب/ادمین (Next.js):** صفحه ۱۳ «مستر کاتالوگ + صف کرالر» و صفحه ۱۴ «دسته‌بندی‌ها و ویژگی‌ها» در گروه محتوای کالا، مطابق `wireframes/admin-panel.png`.
- **مهاجرت / seed / تست / Swagger:** ۴ مهاجرت نسخه‌بندی‌شده + rollback آزمایشی در staging؛ `seed/categories.sql` و `seed/master-products-500.sql`؛ تست‌های واحد و قراردادی بخش ۴؛ پوشش Swagger ۱۰۰٪ در `/docs`.

**خارج از اسکوپ:**
- ثبت لیستینگ، قیمت/موجودی فروشنده، پیش‌بررسی محصول و صف تأیید محصول → **SP-05**.
- نمایش قیمت، موجودی، سبد و چک‌اوت در `product.png` / `cart.png` / `checkout.png` → **SP-05 / SP-06**.
- موتور اعلان و کرون یادآوری ۵ دقیقه‌ای → **SP-11** (اینجا فقط شمارش معکوس SLA داخل UI ادمین).
- جستجوی وزن‌دار و autocomplete → **SP-12**.
- نقش‌های RBAC کامل، 2FA و ۴۸ صفحه ادمین → **SP-15** (اینجا فقط دو صفحه صف).

## ۳. اقدامات و مراحل (گام‌به‌گام با Milestone)

### M-03.1 — اسکیما و مهاجرت‌ها (روز D1-D2)
1. ایجاد `apps/api/src/migrations/00X-catalog.sql`: جداول `categories`, `master_products`, `price_bands`, `product_variants` با `id UUIDv7`، پول `NUMERIC(18,0)`، `created_at/updated_at`، soft-delete با `deleted_at`.
2. ایندکس‌ها: `master_products(category_id)`, `master_products(status)`, `price_bands(master_id UNIQUE)`.
3. قید یکپارچگی: `min_30d <= median_30d <= max_30d`.
4. نوشتن بخش rollback و اجرای `npm run migration:run` سپس `npm run migration:rollback` روی staging.
5. اجرای `seed/categories.sql` (درخت دسته‌ها + ۷ نوع حیوان).

| خروجی مرحله | ۴ جدول + درخت دسته‌ها در dev و staging، مهاجرت برگشت‌پذیر |
| معیار قبولی | rollback بدون خطا؛ خروجی `\d price_bands` دقیقاً ۴ ستون فیلد را نشان دهد |

### M-03.2 — هسته کرالر ۴ منبع (روز D3-D4)
1. ساخت ماژول `apps/api/src/crawler/` با ۴ Adapter جدا: `digikala`, `baranpet`, `isfahanpet`, `brand-official`.
2. هر Adapter قبل از نخستین درخواست `robots.txt` میزبان را واکشی و کش می‌کند؛ مسدودشده ← بدون درخواست + ثبت دلیل.
3. Rate limiter سراسری: **حداکثر ۱ درخواست در هر ۳ ثانیه per host** + backoff نمایی در شکست + صف درون‌برنامه‌ای.
4. User-Agent شفاف در همه درخواست‌ها (متن پیشنهادی: `AMPET-Crawler/1.0 (+https://ampet.ir/bot)` — نهایی‌شدن با کارفرما).
5. زمان‌بندی: **دیجی‌کالا، باران پت، اصفهان پت = روزانه؛ سایت رسمی برندها (رویال‌کنین و مشابه) = ماهانه** (تایم‌زون تهران).
6. نوشتن خروجی خام در `specs(JSON)` + `source_url` + `crawled_at`؛ شناسایی کالای جدید ← `status = PENDING_REVIEW`.
7. تست دستی روی یک URL واقعی از هر ۴ منبع + بررسی لاگ درخواست‌ها.

| خروجی مرحله | کرالر اجراپذیر با `npm run crawler:run -- --source=digikala` |
| معیار قبولی | در اجرای ۶۰ ثانیه‌ای روی یک میزبان ≤ ۲۰ درخواست با فاصله ≥ ۳ ثانیه؛ تست robots سبز |

### M-03.3 — بازه قیمتی و دروازه دارو/مکمل (روز D5)
1. محاسبه `min_30d / median_30d / max_30d` از قیمت‌های ۳۰ روز اخیر ۳ منبع قیمتی (**دیجی‌کالا، باران پت، اصفهان پت** — سایت برند فقط حقیقت نام/بارکد/عکس می‌دهد و در `price_bands` نقشی ندارد).
2. قاعده بلاک: هر قیمت خارج از `[median_30d × 0.6 , median_30d × 1.4]` ← HTTP 422 با پیام دقیق **«خارج از بازه بازار (میانه ±۴۰٪)»**.
3. برچسب `requires_manual_approval = true` برای دسته دارو/مکمل: بدون `approve` دستی ادمین در هیچ خروجی عمومی نمایش داده نمی‌شود.
4. تست واحد مرزها: با میانه ۱۰٬۰۰۰ ← ۶٬۰۰۰ و ۱۴٬۰۰۰ قبول، ۵٬۹۹۹ و ۱۴٬۰۰۱ رد.

| خروجی مرحله | سرویس `price-band` + `drug-gate` |
| معیار قبولی | تست‌های مرزی سبز؛ هیچ قلم دارویی بدون تأیید دستی منتشر نشود |

### M-03.4 — صف تأیید ادمین + صفحات وب (روز D6-D7)
1. پیاده‌سازی ۶ endpoint بخش ۱ با Guard نقش ادمین + 2FA؛ `reject` بدون دلیل ← `VALIDATION_ERROR`.
2. هر تصمیم ← ردیف `audit_logs` با (کاربر، زمان، IP، مقدار قبل/بعد).
3. صفحه ۱۳: مرتب‌سازی قدیمی‌ترین اول + شمارش معکوس SLA (**عادی ۲۴ ساعت / دارو و بهداشتی ۷۲ ساعت**) + Badge هشدار فراتر از SLA + فیلتر وضعیت/منبع + صفحه‌بندی ۲۰ پیش‌فرض / ۱۰۰ سقف.
4. صفحه ۱۴: درخت دسته‌ها (افزودن/ویرایش/تغییر ترتیب/آیکون) با پیش‌نمایش.
5. رعایت دیزاین‌سیستم: primary `#0F5D4A`، accent `#D4AF37`، فونت Vazirmatn، RTL، ارقام فارسی، دکمه ۴۸dp.
6. Rate limit مسیرهای ادمین: ۱۲۰ درخواست در دقیقه.

| خروجی مرحله | دو صفحه ادمین + API تصمیم + `audit_logs` |
| معیار قبولی | سناریوهای دستی ۴، ۵ و ۶ بخش ۴ سبز شوند |

### M-03.5 — Seed هدف ۵۰۰ قلم + Swagger + تست‌ها (روز D8-D10)
1. پر کردن مستر تا **۵۰۰ قلم تأییدشده** **(DoD اسپرینت S2 پلن Lean)** از مسیر **الف (کرالر + تأیید دستی)** یا **ب (`seed/master-products-500.sql` — طبق چک‌پوینت D4، تصمیم D-111)**؛ شمارش نهایی مستقل از مسیر است.
2. بررسی اینکه برای هر قلم تأییدشده ردیف `price_bands` پر و `updated_at` خالی نباشد. (در مسیر ب: `price_bands` بخشی از خود فایل seed است.)
3. تولید Swagger از کد و تطبیق ۱۰۰٪ مسیرهای بخش ۱ در `/docs`.
4. نوشتن تست‌های نام‌برده بخش ۴ و سبز کردن آن‌ها در CI (GitHub Actions).
5. به‌روزرسانی ERD (dbdiagram/Mermaid) در `docs/` و پیوستن به نسخه نهایی.

| خروجی مرحله | ۵۰۰ قلم مستر + `price_bands` کامل + Swagger + تست‌های سبز |
| معیار قبولی | `SELECT count(*) FROM master_products WHERE status='APPROVED'` ≥ ۵۰۰ (مسیر کرالر یا seed — D-111)؛ `npm run test && npm run test:contract` بدون خطا |

## ۴. روش تست و پذیرش (Definition of Done)

**تست خودکار (نام فایل‌ها):**
`crawler.rate-limit.spec.ts` (۱ درخواست/۳ ثانیه per host) · `crawler.robots.spec.ts` (مسیر ممنوع ← بدون درخواست) · `crawler.user-agent.spec.ts` (UA شفاف) · `price-band.calc.spec.ts` (min/median/max 30 روزه) · `price-band.gate.spec.ts` (مرز دقیق ±۴۰٪) · `master.drug-gate.spec.ts` (دارو فقط با approve دستی) · `categories.tree.spec.ts` (درخت + ممانعت از حذف والد دارای فرزند) · `admin.master-products.contract.spec.ts` (قالب پاسخ + کدهای خطا)

**سناریوی دستی گام‌به‌گام:**
1. ورود با حساب ادمین (2FA) ← منوی «مستر کاتالوگ + صف کرالر» ← مشاهده ردیف‌ها با برچسب منبع و شمارش معکوس SLA.
2. کلیک «اجرای دستی کرالر» ← لاگ ۴ منبع نمایان شود؛ در لاگ شبکه فاصله هر درخواست ≥ ۳ ثانیه و UA شفاف باشد.
3. باز کردن یک قلم دارویی ← برچسب «در انتظار تأیید دستی» و نبودِ آن در `GET /categories` خروجی عمومی.
4. ثبت قلمی با قیمت بالاتر از `median_30d × 1.4` ← **422** با پیام دقیق **«خارج از بازه بازار (میانه ±۴۰٪)»** (پیوست ب قرارداد، سناریو ۳).
5. «رد» بدون دلیل ← 400 `VALIDATION_ERROR`؛ با دلیل ← وضعیت رد + ردیف `audit_logs` با IP و دلیل.
6. ورود با حساب فروشنده و فراخوانی `POST /admin/master-products/{id}/approve` ← **403 `FORBIDDEN_ROLE`**.
7. فروشنده `POST /admin/crawler/run` ← 403 `FORBIDDEN_ROLE`.
8. `GET /categories` بدون توکن ← 200 با درخت کامل (عمومی) و صفحه‌بندی استاندارد.
9. پس از seed: شمارش ≥ ۵۰۰ قلم تأییدشده؛ نمای `store.png` حالت خالی «این دسته فعلاً خالی است» را درست نشان دهد.

**خطاهای پرتکرار:**

| کد | HTTP | معنی | مکان پرتکرار |
|----|------|------|--------------|
| `VALIDATION_ERROR` | 400 | بدنه نامعتبر / دلیل خالی | رد بدون دلیل |
| `TOKEN_EXPIRED` | 401 | توکن منقضی | نشست ادمین ۱۰ دقیقه‌ای |
| `FORBIDDEN_ROLE` | 403 | نقش مجاز نیست | فروشنده روی `/admin/**` |
| `NOT_FOUND` | 404 | شناسه ناموجود | `master_id` اشتباه |
| `PRICE_OUT_OF_BAND` (تصمیم — بخش پایان) | 422 | خارج از `میانه ±۴۰٪` | ثبت/ویرایش قیمت |
| `RATE_LIMIT_EXCEEDED` | 429 | سقف نرخ + هدر `Retry-After` | ادمین >۱۲۰/دقیقه، عمومی >۶۰/دقیقه |
| `INTERNAL_ERROR` | 500 | خطای داخلی | شکست یک Adapter کرالر |

**DoD checklist:**
- [ ] ۴ جدول با نام دقیق ERD مهاجرت و rollback شده‌اند
- [ ] کرالر ۴ منبع با robots + سقف ۱ درخواست در ۳ ثانیه + User-Agent شفاف
- [ ] `price_bands` برای همه اقلام تأییدشده پر است و بلاک ±۴۰٪ کار می‌کند
- [ ] دارو/مکمل فقط با تأیید دستی ادمین وارد مستر می‌شود
- [ ] صف ادمین: قدیمی‌ترین اول + SLA ۲۴h/۷۲h + ثبت `audit_logs`
- [ ] Seed ≥ **۵۰۰ قلم** مستر تأییدشده (کرالر **یا** `seed/master-products-500.sql` — تضمین D-111)
- [ ] پوشش Swagger ۱۰۰٪ + همه تست‌های بخش ۴ سبز
- [ ] صفحات ۱۳ و ۱۴ ادمین و `store.png` تحویل شدند

### تصمیم مصوب **D-111 — تضمین تحویل ۵۰۰ قلم مستر (حل ریسک #۶ کرالر)**

> همه ریسک‌های موجود در این جدول (تغییر ساختار HTML، بلاک IP، نبود قیمتِ منبع) به یک نقطه می‌رسند: **شمارش ≥ ۵۰۰ قلم تأییدشده در D9 نباید به دسترس‌پذیری هیچ منبع خارجی گره بخورد.** این تصمیم، کرالر را «منبع ترجیحیِ داده» می‌کند، نه «منبع تضمینیِ تحویل».

| بند | قاعده |
|-----|-------|
| ۱ | **مسیر ترجیحی (پیش‌فرض):** اجرای کامل M-03.2 تا M-03.4 — کرالر ۴ منبع با robots.txt + سقف ۱ درخواست/۳ ثانیه + UA شفاف. |
| ۲ | **محرک تعویض مسیر (چک‌پوینت D4):** اگر تا پایان D4 **حداقل ۲ منبع از ۴** معیار قبولی M-03.2 (اجرای ۶۰ ثانیه‌ای ≤۲۰ درخواست و تست robots سبز) را پاس نکرده‌اند — از هر دلیل (تغییر HTML، بلاک IP، شکست robots) — مسیر اصلی از D5 به **مسیر تضمینی** تغییر می‌کند و این تغییر در `audit_logs` و گزارش D9 ثبت می‌شود. |
| ۳ | **مسیر تضمینی — `seed/master-products-500.sql`:** فایل seed رسمی (نه data‌مصرفی، نه پشتیبان) با **دقیقاً همان اسکیمای مستر** و دو بخش: **(الف)** اقلام استخراج‌شده از نتایج کرال موفق (اثبات زنجیره اند‌تو-اند) + **(ب)** اقلام دست‌ساز از فهرست مصوب کارفرما با `price_bands` کامل (`source='manual_seed'`، `requires_manual_approval` مطابق دسته دارو/مکمل). |
| ۴ | **مرز مسئولیت:** ۵۰۰ قلم نهایی D9 از مسیر الف یا ب هر دو معتبر است؛ سهم هر مسیر/منبع در گزارش D9 ذکر می‌شود. |
| ۵ | **قانونی (بند ۳ پیش‌نیازها):** اقلام seed فقط از فهرستی که کارفرما کتباً در D1-D4 تأیید کرده (فهرست ۴ منبع + فهرست دارو/مکمل و کلمات ممنوعه). |
| ۶ | **حذف ریسک زمان:** با فعال‌شدن مسیر ب، M-03.5 «منتظر کرالر» نمی‌ماند: استخراج seed از D4 شروع، تا D8 ≥۴۵۰ قلم، D9 تأیید نهایی + شمارش ≥۵۰۰. |
| ۷ | **خارج از این تصمیم:** خود کرالر حذف نمی‌شود؛ ۴ Adapter + robots + نرخ‌گیر طبق M-03.2 ساخته و تست می‌شوند تا پس از تحویل، داده واقعی جایگزین seed شود. |

**اعمال روی M-03.5:** گام ۱ اجرای کرالر «یا» بارگذاری `seed/master-products-500.sql` (طبق بند ۲ و ۳)؛ معیار قبولی همان `count(*) ≥ 500` — **مستقل از مسیر**.
