## ۱. هدف، Deliverable و خارج از اسکوپ

- **هدف:** پیاده‌سازی دفتر آدرس مشتری (CRUD + آدرس پیش‌فرض + اعتبارسنجی سمت سرور)، پرونده حیوان خانگی (پایه فاز ۱: اطلاعات پایه، سلامت، سوابق پزشکی، واکسن، انگل‌زدایی، اشتراک‌گذاری ۷ روزه با QR) و سازوکار پذیرش نسخه‌بندی‌شده قوانین — تکمیل‌کننده بخش «آدرس + حیوان پایه» مایل‌ستون M1.
- **Deliverable (تحویل‌نامه):**
  - جداول گروه ۲ ERD: **`addresses`، `seller_addresses` (فقط ساختار — رزرو)، `pets`، `pet_health`، `pet_medical_records`، `pet_vaccinations`، `pet_dewormings`، `pet_share_links`** با کلید `UUIDv7`، `deleted_at` و `created_at/updated_at`
  - Endpointهای آدرس: `GET /api/v1/addresses`، `POST /addresses`، `PATCH /addresses/{id}`، `DELETE /addresses/{id}`
  - Endpointهای حیوان (نمونه‌های API §۸ + توسعه برای CRUD کامل): `GET /pets`، `POST /pets`، `GET/PATCH/DELETE /pets/{id}`، `GET/PATCH /pets/{id}/health`، `GET/POST /pets/{id}/records`، `PATCH /pets/{id}/records/{rid}`، `GET/POST /pets/{id}/vaccinations`، `GET/POST /pets/{id}/dewormings`، `POST /pets/{id}/share`، `DELETE /pets/{id}/share/{sid}`، **`GET /pets/share/{token}`** (بدون نیاز به ورود)
  - Endpointهای قوانین **(تصمیم:** اسناد فقط قاعده داده‌اند**)**: `GET /terms` (نسخه فعال هر سند + تاریخ اجرا)، `POST /terms/accept`، `GET /me/terms` (فهرست پذیرش‌های من)
  - Seed داده: لیست استان/شهر رسمی (JSON)، نژادها per نوع حیوان + «سایر (دستی)»، انواع حیوان (سگ، گربه، پرنده، اگزوتیک، دام بزرگ، اسب، جوندگان، خزنده)، انواع رویداد پزشکی (ویزیت/آزمایش/جراحی/درمان/بستری/مصدومیت)
  - اپ Flutter: صفحات **`wireframes/address.png`** (بخش آدرس/گیرنده — بخش بازه تحویل متعلق به SP-06) و **`wireframes/pet-profile.png`** (کارت هویت، آمار سریع، آلرژی، تب‌ها، سوابق) + «آدرس‌های من»، «افزودن/ویرایش آدرس»، «حیوانات من»، «افزودن حیوان»، «سوابق پزشکی»، «واکسیناسیون»، «اشتراک‌گذاری پرونده»
  - پنل وب: صفحه پایه «نظارت بر پرونده حیوانات» (صفحه ۴۸ از ۴۸: آمار + اشتراک‌های فعال)
  - مهاجرت‌ها + seed + ورودی Swagger + تست‌های واحد/قرارداد + **(تصمیم)** تولید QR با کتابخانه `qr_flutter` از URL اشتراک

- **خارج از اسکوپ این SP:**
  - **`seller_addresses`:** جدول در این SP فقط **ساخته می‌شود** (تکمیل گروه ERD)؛ endpoint، فرم فروشنده و **تأیید ادمین** (نسخه‌بندی + صفحه ۱۱ پنل) → **SP-04** (صفحه ادمین آن SP-15)
  - بازه ساعت تحویل (S1 تا S5)، انتخاب آدرس در چک‌اوت → **SP-06**
  - یادآوری واکسن **۷ روز و ۱ روز قبل** (پوش + پیامک) → **SP-11**؛ این SP فقط `due_date`/`reminder_on` را ثبت می‌کند
  - دانلود PDF کارت واکسن → **(تصمیم:** به‌دلیل سقف ۵ روز کاری، در **SP-11** کنار موتور گزارش‌سازی انجام می‌شود؛ نیاز فوری = الحاقیه**)**
  - ویرایش/نسخه‌بندی **محتوای** صفحات قانونی (ویرایشگر ادمین/اکانتنت) → **SP-14**
  - قفل سفارش/رزرو جدید تا پذیرش قوانین جدید: هوک آن در چک‌اوت → **SP-06** (این SP فقط `TERMS_NOT_ACCEPTED` را تولید می‌کند)
  - لینک‌های مرتبط پرونده (نوبت‌ها/نسخه‌ها/سفارش‌ها/بیمه) → فاز ۲ (رزرو = فاز ۲ — `PLAN §۲`)

- **سناریوی دستی گام‌به‌گام (برای کارفرما):**
  1. وارد شوید ← «آدرس‌های من» ← «افزودن آدرس» → انتظار: حالت خالی «هنوز آدرسی ثبت نکرده‌اید».
  2. کد پستی ۹ رقمی → **«کد پستی ۱۰ رقم است»**؛ شماره گیرنده `0912345` → خطای شماره (۱۱ رقم، شروع `۰۹`)؛ آدرس ۱۰ کاراکتری → رد (حداقل ۱۵ کاراکتر).
  3. استان و شهر را از منو انتخاب کنید (تایپ آزاد ممکن نیست) ← ذخیره → انتظار: آدرس بلافاصله در لیست با نشان پیش‌فرض.
  4. آدرس دوم ثبت و پیش‌فرض کنید ← آدرس اول را حذف کنید → انتظار: حذف انجام و پیش‌فرض خودکار به آدرس باقی‌مانده منتقل شود (پیام خطا «حداقل یک آدرس باید پیش‌فرض باشد» فقط اگر هیچ آدرسی نماند).
  5. آدرس ۱۱ام ثبت کنید → انتظار: خطای سقف ۱۰ آدرس **(تصمیم:** متن: «حداکثر ۱۰ آدرس می‌توانید ثبت کنید»**)**.
  6. «حیوانات من» ← «افزودن حیوان» ← نام «شکاری»، نوع سگ، جنسیت نر، وزن `500` → **«وزن باید بین ۰٫۱ تا ۳۰۰ کیلوگرم باشد»**؛ تولد فردا → **«تولد نمی‌تواند در آینده باشد»**.
  7. ۲۰ حیوان ثبت کنید ← بیست‌ویکم → **«سقف ۲۰ حیوان تکمیل شده است»**.
  8. در «سلامت» آلرژی «مرغ (شدید)» ثبت کنید ← پرونده را باز کنید → انتظار: هشدار قرمز آلرژی در بخش هشدارهای مهم.
  9. یک سابقه پزشکی با ۲ پیوست ثبت کنید؛ ۲۴ ساعت بعد (یا با دستکاری `created_at` در تست) ویرایش کنید → **«ویرایش سوابق پزشکی فقط تا ۲۴ ساعت ممکن است»**؛ ۱۱امین پیوست → رد.
  10. «اشتراک‌گذاری پرونده» ← «ایجاد لینک» → انتظار: لینک + QR با انقضای ۷ روز؛ باز کردن لینک در مرورگر **بدون ورود** → فقط فیلدهای مجاز دیده شود؛ «لغو» → فوراً غیرفعال.
  11. لینک را ۷ روز بعد (یا با `expires_at` دستی) باز کنید → **«این لینک منقضی شده است»** (پیوست ب، سناریو ۱۰: اشتراک پرونده پس از ۷ روز → منقضی).
  12. «حذف حیوان» ← تأیید → انتظار: با نوبت آینده (فاز ۲) فقط غیرفعال می‌شود؛ بدون نوبت، حذف با تأیید دوم.
  13. صفحه قوانین را باز کنید ← «می‌پذیرم» → انتظار: سند پذیرش با **نسخه، زمان، IP، دستگاه** ثبت شود؛ بدون پذیرش، `POST` سفارش (تست موقت) = 422 `TERMS_NOT_ACCEPTED` **«برای ادامه باید قوانین را بپذیرید»**.
  14. متن UI را با UI Copy چک کنید: «پرونده {نام}»، «حیوانات من»، «آدرس‌های من»، حالت‌های خالی دقیق.
- **خطاهای پرتکرار این SP:**

  | HTTP | code | متن دقیق / شرط |
  |------|------|----------------|
  | 400 | `VALIDATION_ERROR` | «کد پستی ۱۰ رقم است»، «شماره موبایل معتبر نیست»، «تولد نمی‌تواند در آینده باشد»، «وزن باید بین ۰٫۱ تا ۳۰۰ کیلوگرم باشد» |
  | 404 | `NOT_FOUND` | «پرونده یافت نشد» / «پرونده یافت نشد» برای حیوان حذف‌شده |
  | 409 | `ADDRESS_IN_USE` **(تصمیم)** | «این آدرس سفارش در جریان دارد — ابتدا غیرفعال کنید» |
  | 409 | `RECORD_EDIT_WINDOW_CLOSED` **(تصمیم)** | «ویرایش سوابق پزشکی فقط تا ۲۴ ساعت ممکن است» |
  | 422 | `ADDRESS_DEFAULT_REQUIRED` **(تصمیم)** | «حداقل یک آدرس باید پیش‌فرض باشد» |
  | 422 | `PET_LIMIT_REACHED` **(تصمیم)** | «سقف ۲۰ حیوان تکمیل شده است» |
  | 422 | `PET_HAS_ACTIVE_BOOKING` **(تصمیم)** | «این حیوان نوبت آینده دارد - ابتدا نوبت را لغو کنید» |
  | 422 | `SHARE_LINK_EXPIRED` **(تصمیم)** | «این لینک منقضی شده است» |
  | 422 | `TERMS_NOT_ACCEPTED` | «برای ادامه باید قوانین را بپذیرید» |
  | 429 | `RATE_LIMIT_EXCEEDED` | سقف عمومی ۶۰/دقیقه + هدر `Retry-After` |
