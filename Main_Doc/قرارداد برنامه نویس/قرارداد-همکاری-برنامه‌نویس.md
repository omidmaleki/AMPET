## ماده ۱ — تعاریف

1. **پروژه:** سوپر اپ AMPET شامل اپ موبایل، پنل وب فروشنده/ادمین، بک‌اند میکروسرویس و زیرساخت، طبق اسناد مبنا.
2. **اسناد مبنا (ترتیب اعتبار):** ۱) همین قرارداد و الحاقیه‌ها ۲) Technical Architecture نسخه ۱٫۰ مورخ ۱۴۰۵/۰۷/۱۴ ۳) Proposal ۴) project-document.md ۵) وایرفریم‌های `wireframes/`. در تعارض، سند بالاتر ملاک است مگر خلاف آن کتباً قید شود.
3. **فاز ۱ (MVP):** مارکت‌پلیس + پروفایل + Auth OTP + پرداخت/کیف پول/تسویه + تأیید فروشنده + تأیید محصول + چت + تیکت + تخفیف + امتیاز/نظر/علاقه‌مندی + آدرس + موجودی + فاکتور + ادمین پایه. جزئیات در پیوست الف.
4. **خارج از اسکوپ فاز ۱:** بیمه، حامی کارت، پت‌تکسی، کافه پت، دام بزرگ/اسب، گرومینگ در محل، اپ سخت‌افزاری — مگر الحاقیه فاز ۲ تا ۴.
5. **پذیرش (Acceptance):** تأیید کتبی کارفرما پس از تست UAT طبق پیوست ب.
6. **باگ حیاتی:** اختلال در پرداخت/اسکرو/لاگین/ثبت سفارش/تحویل با کد ۶ رقمی که سرویس را متوقف کند.

## ماده ۲ — موضوع قرارداد

توسعه، تست، استقرار و تحویل فاز ۱ AMPET طبق استک فریز شده زیر، با قابلیت گسترش به فاز ۲ تا ۴ بدون بازنویسی (API نسخه‌بندی‌شده `/api/v1` و جداول رزرو شده فازهای بعد حفظ شود):

| لایه | تعهد مجری |
|------|------------|
| اپ موبایل | Flutter (Dart)، تک کدپایه Android + iOS، RTL کامل، فونت Vazirmatn، ارقام فارسی، تحمل ۱۳۰٪ text-scale، کنتراست ۴.۵:۱ |
| پنل وب | Next.js (React) برای فروشنده + ادمین، SSR |
| بک‌اند | Node.js + NestJS، معماری ۱۲ میکروسرویس: Auth, User, Marketplace (+Inventory), Booking, Payment, Notification, Reminder, Search, Insurance*, Transport*, Cafe/Livestock/Boarding*, Crawler Bot, Chat (*: قرارداد API و جدول از حالا، پیاده‌سازی در فاز بعد) |
| داده | PostgreSQL 16 (DB per service)، Redis (OTP/سشن/Hold/RateLimit)، RabbitMQ (at-least-once + idempotent)، Elasticsearch/OpenSearch فارسی |
| فایل | S3-compatible (MinIO یا ابری) — سقف تصویر محصول ۵MB JPG/PNG، پیوست پزشکی ۱۰MB |
| realtime | WebSocket (Socket.IO) برای چت |
| نقشه | OSM / Mapbox |
| مانیتورینگ | Prometheus + Grafana + Sentry، لاگ خطا + هشدار |
| CI/CD | GitHub Actions (یا GitLab CI)، تست قراردادی، محیط‌های `dev / staging / prod` جدا |
| پیامک/ایمیل | کاوه‌نگار یا مشابه داخلی + SES/SMTP سازمانی، فقط طبق قالب‌های ثابت سند |
| پرداخت | درگاه بانکی مستقیم + زرین‌پال + کیف پول + اعتبار، اسکرو تا تحویل |
| انتشار | Google Play + بازار + App Store، نسخه‌بندی و آپدیت اجباری/اختیاری |

اصول الزامی: API-first با Swagger زنده در `/docs`، DB per service بدون join مستقیم، مالی event-driven با `Idempotency-Key`، snapshot مالی در سفارش/فاکتور، soft delete + `audit_logs` (کاربر، زمان، IP، قبل/بعد)، پیک بدون اکانت (فقط لینک وب تک‌سفارش ۲۴ ساعته)، پول `NUMERIC(18,0)` ریال، کلید `UUIDv7`، شبا با AES-256، TLS 1.2+، تایم‌زون تهران.

## ماده ۳ — اسکوپ تفصیلی و تحویل‌ها (Sprint 0 تا تحویل)

### ۳.۱ اسپرینت صفر (هفته ۱-۲، پیش‌نیاز پرداخت پیش‌پرداخت)
راه‌اندازی ریپو (Git)، محیط‌ها، CI/CD، دیزاین‌سیستم (رنگ `0F5D4A` / `D4AF37`)، Swagger پایه، ERD اولیه، بک‌لاگ اسپرینت‌ها. خروجی: لینک ریپو + آدرس `dev` + سند بک‌لاگ.

### ۳.۲ تحویل‌های فاز ۱
1. Auth: OTP موبایل (کد ۵ رقمی، تایمر ۱۲۰ ثانیه، ۳ درخواست/۱۰ دقیقه، قفل ۱۵ دقیقه پس از ۳ تلاش ناموفق)، تکمیل پروفایل، پذیرش قوانین، JWT کوتاه (۱۵ دقیقه، ادمین ۱۰ دقیقه + 2FA مالی)، رفرش ۳۰ روزه چرخشی.
2. فروشنده: ثبت‌نام ۱۰ نوع + فقط ۲ ترکیب مجاز (بیمارستان+پانسیون، پت‌شاپ+کلینیک)، مدارک اختصاصی هر نوع، وضعیت‌ها (در انتظار/تأیید/نقص/رد/معلق/غیرفعال)، چک‌لیست ۵ موردی ادمین، مهلت نقص ۷ روز، SLA یادآوری ۷ روز.
3. مستر + لیستینگ: مستر فقط با کرالر (دیجی‌کالا/باران پت/اصفهان پت/سایت برند) + تأیید ادمین؛ فروشنده فقط لیست می‌کند (قیمت/موجودی، بلاک خارج از میانه ±۴۰٪)، صف ادمین SLA ۲۴ ساعته (دارو ۷۲ ساعته)، تعلیق ۷ روزه پس از ۳ رد متوالی.
4. فروش: سبد چندفروشگاهی (N سفارش مستقل، یک پرداخت)، Hold موجودی anti-oversell، چک‌اوت (آدرس + بازه تحویل + هزینه فروشگاهی + درگاه/کیف پول/اعتبار + تخفیف/امتیاز)، اسکرو، تحویل با کد ۶ رقمی هش‌شده + عکس، تسویه ۱۴ روزه، فاکتور + درخواست فاکتور رسمی.
5. لغو/مرجوعی/بازگشت: جدول لغو سفارش و نوبت، پنجره مرجوعی، بازگشت به کیف پول ۰ تا ۱۰ ثانیه + برداشت بانکی ۱۴ روزه، retry دستی (بدون retry خودکار مالی).
6. تعامل: چت thread-per-سفارش/رزرو، تیکت (لیست/جدید/جزئیات + ۳ پیوست)، اعلان پوش/پیامک/ایمیل/In-App طبق قالب‌ها، جستجوی وزن‌دار فارسی، علاقه‌مندی، نظر ستاره تفکیکی + عکس/ویدیو، امتیاز وفاداری، کد تخفیف (فروشگاهی با سقف ادمین)، کد معرف.
7. پرونده حیوان (پایه فاز ۱): CRUD حیوان + سلامت، سوابق پزشکی/واکسن، اشتراک لینک ۷ روزه + QR (توسعه کامل پرونده در فاز ۲).
8. ادمین پایه: ۲۰ قابلیت (کاربران، فروشگاه، محصول، سفارش، نوبت، تخفیف، محتوا، تیکت، گزارش، تنظیمات، نقش RBAC، نظر، مالی، اعلان گروهی، لاگ، API) + داشبورد + لاگ کامل.
9. غیرعملکردی: صفحه‌بندی (۲۰ پیش‌فرض، ۱۰۰ سقف، فید cursor)، RateLimit (عمومی ۶۰/دقیقه، پرداخت ۱۰/دقیقه، ادمین ۱۲۰/دقیقه)، بدنه ۵MB سقف، خطاهای فارسی UI Copy، پاسخ استاندارد `{success,data,meta}` و `{success:false,error{code,message,details,request_id}}`.

پیوست الف چک‌لیست ۴۰ صفحه مشتری + ۲۲ صفحه فروشنده + ۲۸ وایرفریم را ملاک پذیرش می‌کند. هر قلم خارج از این لیست = تغییر اسکوپ (ماده ۷).

## ماده ۶ — مالکیت، ریپو و تحویل نهایی

1. مالکیت کامل کد، دیتابیس، مستندات، دیزاین و دانش فنی فاز ۱ پس از تسویه نهایی متعلق به کارفرماست.
2. مجری موظف است از روز اول روی ریپوی متعلق به کارفرما (GitHub/GitLab …) با دسترسی کامل ادمین کارفرما کار کند؛ هیچ کدی خارج از ریپو نگه‌داری نشود.
3. تحویل نهایی شامل: سورس کامل + تاریخچه Git، فایل `.env.example` (بدون سکرت واقعی)، اسکریپت مهاجرت + seed، Swagger/OpenAPI، ERD نهایی، ران‌بوک استقرار/بکاپ/بازیابی، دسترسی `prod` + کلیدها، انتقال استورها و دامنه‌ها، جلسه انتقال دانش (حداقل ۴ ساعت ضبط‌شده).
4. تا پیش از تسویه کامل، کارفرما حق استفاده آزمایشی دارد؛ حق فروش/واگذاری ندارد. پس از تسویه، لایسنس‌ها و اکانت‌ها به نام کارفرما منتقل می‌شود.
5. کتابخانه‌های open-source فقط با لایسنس سازگار تجاری (MIT/Apache-2.0) مجازند؛ کپی کد دارای کپی‌رایت شخص ثالث ممنوع و مسئولیتش با مجری است.

## ماده ۷ — تغییر اسکوپ (Change Request)

هر تغییر (صفحه جدید، سرویس جدید، تغییر استک فریز شده، تغییر قانون کسب‌وکاری مثل درصد کارمزد یا سقف بیمه) فقط با فرم کتبی الحاقیه: شرح، اثر بر زمان/مبلغ، و امضای طرفین. مجری حق ندارد بدون الحاقیه فاکتور اضافه صادر کند؛ کارفرما حق ندارد بدون الحاقیه تحویل اضافه بخواهد. تغییرات زیر ۸ ساعت در هر اسپرینت با توافق شفاهی/پیامی قابل انجام و در صورت‌جلسه ثبت می‌شود.

## ماده ۸ — تست، پذیرش و گارانتی

1. مجری برای هر مایل‌ستون تست واحد + تست قراردادی API + تست دستی سناریوهای پیوست ب ارائه می‌کند.
2. UAT نهایی: کارفرما ظرف ۱۰ روز کاری تست می‌کند؛ باگ‌ها در ۳ دسته (حیاتی ۴۸ ساعته، مهم ۷ روزه، جزئی ۱۴ روزه) رفع می‌شوند. پس از رفع حیاتی/مهم، صورت‌جلسه پذیرش امضا می‌شود.
3. گارانتی رفع باگ: … ماه (پیشنهاد ۶ ماه) پس از پذیرش، رایگان. شامل باگ‌های مغایر با اسناد مبنا. فیچر جدید شامل نیست.
4. پشتیبانی پس از گارانتی طبق SLA سالانه: پاسخ حیاتی ۴ ساعت، رفع ۲۴ ساعت؛ مهم ۸/۷۲ ساعت؛ پایش Sentry + بکاپ روزانه دیتابیس با نگهداری ۳۰ روزه (تعهد مجری در دوره پشتیبانی).
5. معیارهای فنی پذیرش: پوشش Swagger ۱۰۰٪ endpointها، مهاجرت برگشت‌پذیر تست‌شده در staging، بدون خطای critical در Sentry طی ۷ روز، امتیاز Lighthouse پنل وب بالای ۸۰، کرش‌فری اپ بالای ۹۹.۵٪ در تست داخلی.

## ماده ۹ — جریمه‌ها و مسئولیت‌ها

1. تأخیر مجری در هر مایل‌ستون: …٪ مبلغ آن مایل‌ستون به ازای هر روز (پیشنهاد ۰.۲٪)، سقف ۱۰٪. تأخیر بیش از ۳۰ روز = حق فسخ کارفرما + استرداد علی‌الحساب بخش تحویل‌نشده.
2. تأخیر کارفرما در پرداخت/بازخورد: تمدید معادل + حق توقف مجری پس از اخطار ۷ روزه.
3. نشت اطلاعات کاربران/فروشندگان به دلیل قصور فنی مجری (عدم رمزنگاری، لاگ PII، دسترسی ناامن): مسئولیت جبران تا سقف مبلغ قرارداد + رفع فوری. مجری موظف به رعایت حریم خصوصی و عدم ذخیره غیرضروری PII است.
4. قطعی به دلیل عدم پیاده‌سازی idempotency/اسکرو/soft-delete که منجر به ضرر مالی شود: مسئولیت مستقیم با مجری در حد اثبات کارشناسی.
5. فورس‌ماژور (قطعی سراسری اینترنت، تحریم استور، زلزله و…) جریمه ندارد؛ طرفین ظرف ۷ روز راه جایگزین توافق می‌کنند.

## ماده ۱۰ — محرمانگی و عدم رقابت

1. مجری کلیه اطلاعات کسب‌وکاری، داده کاربران، قیمت‌ها و اسناد را محرمانه نگه می‌دارد؛ حتی پس از اتمام (۳ سال).
2. مجری تا … ماه پس از تحویل (پیشنهاد ۱۲ ماه) حق ساخت/فروش پلتفرم مشابه مستقیم (سوپر اپ پت) برای رقیب ایرانی را ندارد مگر با اجازه کتبی. نقض = …٪ مبلغ قرارداد به‌عنوان وجه التزام.
3. کارفرما متعهد است دسترسی‌های حساس (درگاه، سرور) را فقط در حد نیاز بدهد و پس از اتمام بازپس گیرد.

## ماده ۱۱ — فسخ
