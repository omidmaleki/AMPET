## ۱. هدف، Deliverable و خارج از اسکوپ

**هدف:** فروشنده فقط از مستر انتخاب می‌کند و **قیمت + موجودی** می‌زند؛ ساخت محصول دستی ممنوع است. هر لیستینگ قبل از نمایش به مشتری از «پیش‌بررسی خودکار ۱۰ شرطی» و سپس «چک‌لیست ۱۰ موردی ادمین» با SLA **۲۴ ساعت عادی / ۷۲ ساعت دارو و بهداشتی** عبور می‌کند. در همان‌جا موتور **Hold anti-oversell** (۱۵ دقیقه عادی / ۵ دقیقه شلوغ / تمدید ۲۰ و ۳۰ دقیقه / Job هر ۳۰ ثانیه / Row Lock) تحویل می‌شود.

**Deliverable:**

- **جداول (نام ثابت ERD):** `listings` (`id, master_id, seller_id, price, stock, status` — فقط همین فیلدهای تجاری)، `inventory_holds` (`id, listing_id, cart_id, qty, expires_at, released_at`)، `inventory_logs` (`id, listing_id, before, after, reason, actor_id`)، به‌علاوه خواندنی: `master_products`، `price_bands`، `categories`؛ اسکلت `carts` و `cart_items` (تصمیم — بخش ۵)؛ `audit_logs` برای تصمیمات ادمین.
- **Endpointها (زیر `/api/v1`):**

| مسیر | نقش | توضیح |
|------|-----|-------|
| `GET /master-products?q=&category_id=&animal=` | فروشنده | انتخاب از مستر تأییدشده (بدون ساخت محصول) |
| `POST /listings` | فروشنده | فقط `master_id + price + stock` |
| `PATCH /listings/{id}` | فروشنده | ویرایش؛ فیلد حساس ← بازگشت به صف |
| `GET /listings/mine` · `GET /listings/{id}` | فروشنده | لیست با فیلتر وضعیت + دلایل رد |
| `GET /products` · `GET /products/{slug}` | عمومی | فقط لیستینگ‌های `APPROVED` (API §8 Catalog) |
| `POST /cart/items` · `DELETE /cart/items/{id}` · `GET /cart` · `POST /cart/items/{id}/hold` · `GET /cart/hold-status` | مشتری | اسکلت حداقلی سبد + رزرو/شمارش معکوس (API §8 Inventory) |
| `GET /admin/listings?status=pending_review&page=` | ادمین | صف بازبینی + شمارش معکوس SLA |
| `GET /admin/listings/{id}` · `POST /admin/listings/{id}/decision` | ادمین | پرونده + پیش‌نمایش از دید مشتری + چک‌لیست ۱۰ موردی و ثبت تأیید / درخواست اطلاعات / رد / رد دائمی |
| `GET /admin/inventory-report` | ادمین | صفحه ۱۵: محصولات صفر + بیشترین لغو ناشی از اتمام |

- **صفحات Flutter:** `wireframes/add-product.png` (جست‌وجو در مستر ← انتخاب ← قیمت/موجودی ← پیش‌بررسی)، `wireframes/product.png` (وضعیت‌های موجودی + «اعلام موجودی»)، `wireframes/store.png` (لیست و حالت خالی «محصولی با این فیلترها یافت نشد»)، `wireframes/cart.png` (شمارش معکوس رزرو — اسکلت)، `wireframes/seller-dashboard.png` (بخش «محصولات من» با حالت خالی «محصولی ثبت نکرده‌اید»).
- **صفحات وب ادمین:** صفحات ۴ «صف بازبینی محصولات»، ۵ «پرونده بازبینی»، ۶ «تاریخچه تصمیمات»، ۷ «مدیریت محصولات»، ۸ «گزارش محصولات ردشده و علل» و صفحه ۱۵ «گزارش موجودی» — در `wireframes/admin-panel.png`.
- **مهاجرت / seed / تست / Swagger:** ۵ مهاجرت + rollback در staging؛ seed ۲۰ لیستینگ آزمایشی در ۵ وضعیت؛ تست‌های بخش ۴ (شامل تست بار همزمان)؛ پوشش Swagger ۱۰۰٪.

**خارج از اسکوپ:**
- سبد چندفروشگاهی کامل، چک‌اوت، سفارش، بازه تحویل و ماشین لغو → **SP-06** (اسکلت `carts` در این SP فقط برای تست Hold است).
- پرداخت، Row Lock پس از callback درگاه، اسکرو → **SP-07** (اینجا فقط نقطه اتصال `stock.reserved/released`).
- صدور کوپن عذرخواهی ۵٪، «اطلاع‌رسانی موجودی» و پیشنهاد کالای جایگزین → **SP-06 / SP-11 / SP-13**؛ ایندکس جستجوی لحظه‌ای و رتبه‌بندی → **SP-12**؛ تأیید فروشنده و چک‌لیست ۵ موردی → **SP-04**؛ ساخت/تأیید مستر و بازه قیمتی → **SP-03**.

## ۳. اقدامات و مراحل (گام‌به‌گام با Milestone)

### M-05.1 — اسکیما و اسکلت سبد (روز D1-D2)
1. ایجاد `00X-listings-inventory.sql`: `listings`، `inventory_holds`، `inventory_logs` + ایندکس حیاتی `inventory_holds(expires_at)`.
2. `listings.status` با ۱۰ وضعیت دقیق: `DRAFT, PRECHECK_FAILED, PENDING_REVIEW, NEEDS_INFO, APPROVED, REJECTED, REJECTED_PERMANENT, SUSPENDED, UNLISTED, ARCHIVED`.
3. قید یکتایی `(master_id, seller_id)` ← هر فروشنده یک لیستینگ per قلم مستر.
4. اسکلت `carts` / `cart_items` (فیلدهای `hold_expires_at, peak_mode`) + `POST /cart/items` حداقلی؛ سپس rollback در staging + ثبت در `docs/ERD`.

| خروجی مرحله | ۵ جدول + اسکلت سبد |
| معیار قبولی | rollback سبز؛ `\d listings` فقط فیلدهای مجاز را نشان دهد |

### M-05.2 — ایجاد لیستینگ از مستر + دروازه ±۴۰٪ (روز D3)
1. `GET /master-products`: فقط مسترهای `APPROVED` + فیلتر دسته/حیوان/جست‌وجو.
2. `POST /listings`: بدن فقط `master_id, price, stock` — هر فیلد اضافه (نام/عنوان/تصویر) ← `VALIDATION_ERROR`.
3. اعتبارسنجی قیمت: `price` عدد صحیح مثبت (`NUMERIC(18,0)`) و داخل `[median_30d × 0.6 , median_30d × 1.4]`؛ خارج ← **HTTP 422 با پیام «خارج از بازه بازار (میانه ±۴۰٪)»** (**پیوست ب، سناریو ۳**).
4. `price` بیرون از رنج دسته ← «قیمت خارج از محدوده مجاز این دسته است»؛ صفر/منفی ← «قیمت را صحیح وارد کنید»؛ دروازه فروشنده: `sellers.status != APPROVED` ← **403 `FORBIDDEN_ROLE`** (**پیوست ب، سناریو ۲** — فروشنده بدون پروانه/تأیید دسترسی ندارد).

| خروجی مرحله | API ایجاد لیستینگ + دروازه قیمت |
| معیار قبولی | سناریوی دستی ۱ تا ۳ بخش ۴ سبز شود |

### M-05.3 — پیش‌بررسی خودکار ۱۰ شرطی (روز D4)
اجرای هر ۱۰ شرط پیش از ورود به صف (پیام‌ها دقیقاً طبق جدول)؛ شرط‌های ۱،۲،۳،۶،۷،۸،۹،۱۰ روی داده ارث‌بری‌شده از `master_products` و شرط‌های ۴،۵ روی `listings` سنجیده می‌شوند (تصمیم — بخش ۵):

| # | شرط | پیام خطا |
|---|-----|---------|
| ۱ | ۳ تا ۱۲ تصویر | «حداقل ۳ تصویر لازم است» |
| ۲ | عنوان ۱۰ تا ۸۰ کاراکتر | «عنوان باید بین ۱۰ تا ۸۰ کاراکتر باشد» |
| ۳ | توضیحات حداقل ۵۰ کاراکتر | «توضیحات باید حداقل ۵۰ حرف باشد» |
| ۴ | قیمت مثبت و در رنج دسته | «قیمت خارج از محدوده مجاز این دسته است» |
| ۵ | موجودی ≥ ۱ | «موجودی نمی‌تواند صفر باشد» |
| ۶ | دسته سازگار با نوع فروشنده | «دسته با نوع فعالیت شما سازگار نیست» |
| ۷ | حداقل یک نوع حیوان (یا «همه») | «نوع حیوان را انتخاب کنید» |
| ۸ | بدون کلمه ممنوعه | «عبارت غیرمجاز: {عبارت}» |
| ۹ | تصویر ≤۵MB و JPG/PNG | «حجم یا فرمت تصویر نامعتبر است» |
| ۱۰ | بدون لوگو/متن تبلیغاتی بیگانه روی تصویر اصلی | «تصویر اصلی نباید لوگو یا متن تبلیغاتی داشته باشد» |

ناموفق ← `PRECHECK_FAILED` + نمایش همه خطاها هم‌زمان؛ موفق ← `PENDING_REVIEW` + ورود به صف ادمین.

| خروجی مرحله | سرویس پیش‌بررسی + ماشین وضعیت |
| معیار قبولی | ۱۰ تست واحد مرزی (۲/۹ تصویر، ۹/۸۱ کاراکتر، ۴۹ حرف) سبز |

### M-05.4 — صف ادمین + قواعد بازبینی مجدد (روز D5-D6)
1. صف: مرتب قدیمی‌ترین اول + شمارش معکوس **SLA ۲۴ ساعت (عادی) / ۷۲ ساعت (دارو/بهداشتی)**؛ یادآوری خودکار به ادمین پس از **۴ ساعت** + هشدار پس از **۱۲ ساعت**؛ محصول قدیمی‌تر از ۲۴ ساعت ← هشدار در پنل.
2. پرونده بازبینی: **چک‌لیست ۱۰ موردی** (تطابق عنوان/تصویر، صحت قیمت، صحت موجودی، کیفیت تصاویر، طبقه‌بندی، سازگاری نوع حیوان، عدم تبلیغ گمراه‌کننده، ممنوعیت‌های قانونی، عدم کپی، مطابقت شرایط مرجوعی/گارانتی).
3. ۴ تصمیم: **تأیید / درخواست اطلاعات / رد (قابل اصلاح) / رد دائمی** با دلیل اجباری؛ هر تصمیم ← `audit_logs`.
4. تأیید ← `APPROVED` + نمایش در `store.png` و `product.png`؛ رد ← اعلان با دلیل + **شماره تلاش باقی‌مانده (از ۳)**.
5. **۳ رد متوالی ← تعلیق ۷ روزه امکان ثبت محصول جدید** + اعلان + تیکت خودکار؛ ۵ رد دائمی در ۹۰ روز ← بازبینی وضعیت فروشنده (ارجاع به SP-04).
6. **قواعد بازبینی مجدد:** ویرایش فیلد حساس (قیمت/موجودی/تصویر اصلی/دسته/نوع حیوان/عنوان) ← بازگشت به `PENDING_REVIEW`؛ ویرایش غیرحساس ← انتشار فوری + لاگ؛ **افزایش قیمت بیش از ۲۰٪ در ۳۰ روز ← بازبینی مجدد** (**پیوست ب، سناریو ۶**)؛ تأیید دسته‌ای فقط برای فروشندگان با ۳ ماه سابقه بدون تخلف؛ تعلیق فروشنده ← همه محصولاتش `SUSPENDED`.

| خروجی مرحله | صف + چک‌لیست + SLA/یادآوری + قواعد بازبینی |
| معیار قبولی | سناریوی دستی ۴ تا ۷ بخش ۴ سبز شود |

### M-05.5 — موتور Hold و وضعیت‌های موجودی (روز D7-D8)
1. `POST /cart/items/{id}/hold`: **عادی ۱۵ دقیقه / حالت شلوغ حداکثر ۵ دقیقه** (روشن دستی ادمین یا خودکار با بیش از `N` سفارش در ۵ دقیقه اخیر) + نمایش شمارش معکوس.
2. ورود به چک‌اوت ← تمدید تا **۲۰ دقیقه** + re-validate + پیام «موجودی تا ۲۰ دقیقه برای شما رزرو شد»؛ کلیک «پرداخت» ← تمدید تا **۳۰ دقیقه** + اعتبارسنجی نهایی قبل از باز شدن درگاه (اتصال کامل در SP-06/SP-07).
3. **Job آزادسازی هر ۳۰ ثانیه** برای `expires_at` گذشته ← `released_at` + رویداد `stock.released`؛ کسر قطعی با **Row Lock** روی سطر `listings` در تراکنش پرداخت (نقطه اتصال callback — SP-07) + نوشتن هر تغییر در `inventory_logs` (کاربر، زمان، قبل/بعد، دلیل).
4. ۵ وضعیت موجودی: **موجود (>۵)**، **کم (≤۵)** با نمایش «فقط N عدد باقی مانده»، **رزروشده** «در حال رزرو برای خریداران دیگر»، **ناموجود (=۰)** با دکمه اطلاع‌رسانی، **پیش‌فروش** «پیش‌فروش — ارسال از تاریخ X».
5. صفحه «مدیریت موجودی» فروشنده: جدول اقلام + ویرایش دستی + هشدار موجودی کم (سقف پیش‌فرض ≤ ۳) + لاگ تغییرات؛ اگر زیر رزروهای فعال کم شود ← کاهش تا حداکثر مجاز + گزارش تداخل.

| خروجی مرحله | موتور Hold + وضعیت‌ها + صفحه موجودی |
| معیار قبولی | تست بار همزمان: ۲۰ درخواست روی آخرین واحد ← دقیقاً ۱ موفق، ۱۹ پاسخ `STOCK_UNAVAILABLE` |

2. تولید Swagger و تطبیق ۱۰۰٪ مسیرهای بخش ۱.

| خروجی مرحله | تست‌های سبز + Swagger + سناریوهای پیوست ب |
| معیار قبولی | DoD بخش ۴ کاملاً تیک‌خورده |

## ۴. روش تست و پذیرش (Definition of Done)

**تست خودکار (نام فایل‌ها):**
`listing.create-from-master.spec.ts` (فقط master_id+price+stock) · `listing.price-band-gate.spec.ts` (مرز ±۴۰٪) · `listing.precheck.spec.ts` (۱۰ شرط + پیام‌ها) · `listing.status-machine.spec.ts` (۱۰ وضعیت) · `listing.sensitive-edit.spec.ts` (فیلد حساس ← صف) · `listing.price-rise-20pct.spec.ts` (+۲۰٪ در ۳۰ روز) · `listing.rejection-attempts.spec.ts` (۳ رد ← تعلیق ۷ روزه) · `inventory.hold-ttl.spec.ts` (۱۵/۵/۲۰/۳۰ دقیقه) · `inventory.release-job.spec.ts` (هر ۳۰ ثانیه) · `inventory.oversell-load.spec.ts` (Row Lock) · `inventory.stock-status.spec.ts` · `admin.listing-review.contract.spec.ts`

**سناریوی دستی گام‌به‌گام:**
1. (**پیوست ب ۳**) فروشنده تأییدشده ← `add-product.png` ← انتخاب یک قلم مستر ← قیمتی بالاتر از `median_30d × 1.4` ← ذخیره ← **422 و پیام «خارج از بازه بازار (میانه ±۴۰٪)»**؛ اصلاح به قیمت داخل بازه ← پذیرش.
2. (**پیوست ب ۲**) فروشنده با وضعیت «در انتظار تأیید» (کلینیک بدون پروانه) ← `POST /listings` ← **403 `FORBIDDEN_ROLE`**؛ پیام سطح UI: «پروانه فعالیت الزامی است».
3. بدن `POST /listings` با فیلد `title` ← 400 `VALIDATION_ERROR` (ساخت محصول دستی ممنوع).
4. پیش‌بررسی: تصویر ۲ عدد ← «حداقل ۳ تصویر لازم است»؛ عنوان ۹ کاراکتر ← «عنوان باید بین ۱۰ تا ۸۰ کاراکتر باشد»؛ توضیح ۴۹ حرف ← «توضیحات باید حداقل ۵۰ حرف باشد»؛ موجودی ۰ ← «موجودی نمی‌تواند صفر باشد»؛ متن «بدون عوارض» ← «عبارت غیرمجاز: بدون عوارض»؛ تصویر ۶MB ← «حجم یا فرمت تصویر نامعتبر است».
5. ادمین ← صفحه ۴ «صف بازبینی محصولات» ← شمارش معکوس SLA (دارو ۷۲ ساعت) ← پرونده ← تیک ۱۰ مورد چک‌لیست ← «تأیید» ← محصول در `store.png` و `product.png` نمایان شود.
6. «رد» بدون دلیل ← `VALIDATION_ERROR`؛ با دلیل ← اعلان به فروشنده + «شماره تلاش باقی‌مانده (از ۳)»؛ سومین رد ← **تعلیق ۷ روزه** + تیکت خودکار.
7. (**پیوست ب ۶**) فروشنده قیمت تأییدشده را بیش از **۲۰٪ در ۳۰ روز** بالا می‌برد ← وضعیت به `PENDING_REVIEW` برمی‌گردد و از `store.png` ناپدید می‌شود.
8. مشتری ← `product.png` ← «افزودن به سبد» ← شمارش معکوس **۱۵ دقیقه**؛ روشن کردن حالت شلوغ ادمین ← هشدار «به دلیل حجم بالا، مهلت رزرو سبد شما ۵ دقیقه شد».
9. ورود به چک‌اوت ← «موجودی تا ۲۰ دقیقه برای شما رزرو شد»؛ کلیک «پرداخت» ← تمدید تا ۳۰ دقیقه.
10. بدون پرداخت ← انتظار ۳۰ ثانیه + اجرای Job ← آزادسازی + خروج رزرو؛ دو کاربر همزمان روی آخرین واحد ← فقط یکی موفق، دیگری **«موجودی این کالا به پایان رسیده است»** (`STOCK_UNAVAILABLE`).
11. نمایش ۵ وضعیت: «موجود» / «فقط N عدد باقی مانده» (قرمز) / «در حال رزرو برای خریداران دیگر» / «ناموجود» + دکمه اطلاع‌رسانی / «پیش‌فروش — ارسال از تاریخ X»؛ فروشنده ← `seller-dashboard.png` ← «محصولات من» ← برچسب «در انتظار بررسی» و دلایل رد.

**خطاهای پرتکرار:**

| `VALIDATION_ERROR` | 400 | بدن نامعتبر/فیلد ممنوع | ارسال `title` در لیستینگ، رد بدون دلیل |
